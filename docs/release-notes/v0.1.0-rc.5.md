Première version dont la chaîne complète est vérifiée sur les artefacts livrés plutôt que sur
les sources, pour un projet neuf comme pour un projet existant, et dont l'application desktop
est réellement pilotable.

## Cinq défauts corrigés, chacun mesuré sur l’artefact et non déduit

* Les ressources du paquet — trente-neuf migrations SQL — manquaient aux deux emballages
  PyInstaller. Vingt et une sous-commandes de la CLI étaient mortes, `init` compris, c'est-à-dire
  la remédiation que `doctor` prescrivait lui-même ; et le bridge du bureau mourait au lieu de
  refuser.
* Deux entry points d'adapter que le catalogue nommait n'avaient jamais été écrits, et aucun test
  ne couvrait `adapter_catalog`.
* L'ACL Tauri autorisait dix commandes sur quarante-quatre : l'essentiel de l'interface était
  refusé, pendant que toute erreur du backend s'affichait sans sa cause.
* Le bridge encodait sa sortie selon la locale, donc en page de code sous Windows : la première
  réponse accentuée était illisible côté Rust.
* La configuration MCP générée désignait des scripts console qu'aucun artefact de release
  n'embarque, tandis que deux diagnostics sur trois la déclaraient saine.

## Ce que la version apporte
 la CLI porte les deux entry points de l'adapter Claude local, la
fenêtre accepte `--project-root` et se pilote sans écran, et `install` refuse d'écrire une
configuration qu'il ne sait pas lancer.

## Attesté
 suite de conformité, tests backend desktop et construction des bundles verts sur Linux
x64 et Windows x64. Chaîne complète exécutée sur l'artefact livré, `vera_mmu` désinstallé de
l'environnement — projet neuf et projet existant réel, `conclude` rendant « les 18 étapes sont
franchies » avec un code de sortie nul, serveur MCP réel, et interface pilotée sans écran. Le
playbook édité par le projet se retrouve verbatim dans les instructions que le serveur remet à
l'agent.

## Non attesté — et dit, plutôt que passé sous silence

Le pilotage réel — CLI et interface — n'a été exécuté que
sur Linux, et une seule fois. Côté Windows, l'attestation est celle de la CI. Un oracle
`OBSERVED_PROCESS` déclaré pour un projet reste déclaratif : aucune surface livrée n'enregistre
son exécution.

## Installation — ce qui change en rc.5

La CLI autonome porte désormais les deux entry points de l'adapter Claude local,
`claude-code-local-mcp` et `claude-code-local-hook`. `vmmu install --adapter claude-code-local`
écrit donc une configuration exécutable **sans** `pip install` préalable, ce qui n'était pas le
cas des versions précédentes : elles désignaient des scripts console qu'aucun artefact
n'embarquait.

Et `install` refuse désormais d'écrire une configuration dont il ne sait pas résoudre les
commandes, plutôt que de la produire puis de se déclarer sain.

## Vérifier ce que vous téléchargez

Chaque plateforme publie son `SHA256SUMS-<cible>` et son `release-manifest-<cible>.json`. Le
manifest déclare l'empreinte du binaire et la révision source dont il est issu :

```bash
sha256sum -c SHA256SUMS-x86_64-unknown-linux-gnu
python3 -c "import json;m=json.load(open('release-manifest-x86_64-unknown-linux-gnu.json'));print(m['source_revision'])"
```
