# Identité officielle de VERA-MMU

| Surface | Convention |
|---|---|
| Nom public | **VERA-MMU** |
| Graphie de dépôt et de distribution | `vera-mmu` |
| Développement canonique | **Verifiable Epistemics & Relational Architecture** |
| Positionnement court | *A proof-oriented memory, provenance, and governance engine for AI-assisted projects.* |
| Namespace Python | `vera_mmu` |
| CLI | `vmmu` |
| Schéma canonique | `vera://<project>/<resource>/<id>` |
| Répertoire local de runtime | `.vera-mmu/` |

## Signification

**Verifiable** exprime l’exigence de preuve, de hash, de politique, d’audit, de gate et de validation. **Epistemics** exprime la distinction centrale entre hypothèse, observation, exécution, preuve et connaissance promue. **Relational** exprime le graphe typé reliant mémoire, entités, travail, exécutions, preuves et artefacts. **Architecture** désigne le cadre commun qui relie mémoire, orchestration, pipelines, outils, état, agents et workflows.

Le sigle **MMU** est conservé dans le nom de projet pour assurer la continuité historique avec ARET-MMU et situer le système comme une couche de gestion de mémoire et de continuité. L’expansion de VERA demeure toutefois « Verifiable Epistemics & Relational Architecture » ; MMU n’en est pas un terme supplémentaire.

## Discipline de désambiguïsation

Le terme seul `VERA` est déjà employé dans des contextes d’IA et de développement. Toute documentation, commande, package, configuration ou ressource nouvelle doit donc employer la forme composée **VERA-MMU**, `vera-mmu`, `vera_mmu`, `vmmu` ou `vera://` selon sa surface. L’audit de ces collisions est consigné dans [NAMING_AUDIT.md](NAMING_AUDIT.md).
